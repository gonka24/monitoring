# Monitoring

Справочник возможностей, полей и примеров запросов: [HTTP API](docs/api.md).

`POST /v2/deals/search` — прямой поиск в сети по hosts/buyers с деталями найденных сделок.
[Контракт сетевого поиска и ограничения](docs/search.md).

`GET /v1/deals/{address}` возвращает состояние, участников и условия сделки из кэша Factory.
Запуск: `cargo run`; проверка: `curl http://localhost:8080/v1/deals/gonka1kxlsujae2mgahx2grd8hq8clhsk2zwsqk8q8esx6n2cpj426sdts9cdejs`.
`GONKA_REST_URL` задаёт REST base URL (по умолчанию `https://node1.gonka.ai:8443/chain-api`).
`GONKA_RPC_URL` задаёт RPC base URL (по умолчанию `https://node1.gonka.ai:8443/chain-rpc`).
При смене сети задавайте оба URL для одной сети.
HTTP 503 — снимок ещё не готов; 404 — адрес отсутствует в снимке Factory (включая неверный формат).
Маршруты `/v1/deals` читают память без RPC; `updated_at` и `stale` показывают актуальность данных.

Фоновый сборщик заполняет кэш в памяти при старте и обновляет раз в 60 секунд.
Обход ограничен 50 секундами; ошибка сохраняет предыдущий снимок с `stale=true`.
Снимок включает состояния и историю событий всех сделок; они заменяются в памяти вместе.
Ошибка истории также отменяет обновление всего снимка.
История отражает индекс ноды и не гарантирует полноту истории сети.
`GET /v1/deals/{address}/events` возвращает `address`, `events`, `updated_at` и `stale`.
Запись события содержит `transaction_hash`, строковую `height`, `event_index` (с нуля) и `event`.
Известная сделка без событий возвращает `events: []`; неизвестный адрес — 404, холодный кэш — 503.
Первый вариант отдаёт всю собранную историю (до 10 000 событий), без пагинации HTTP.
Список сделок читает кэш: до первого снимка — 503, затем `updated_at` (Unix seconds) и `stale`.

`GET /v1/deals?after=1` читает следующую страницу кэша реестра pilot Factory (до 50 сделок).
Без `after` возвращается первая страница; `next_after=null` означает конец списка.
ID и курсор в JSON — строки, чтобы JavaScript не терял точность u64.

Rust API для будущего мониторинга сделок `gonka24/forward-contracts`.
Подключены чтение состояния, сбор событий и хранение в памяти процесса.

## Быстрый старт

Установите Rust через https://rust-lang.org/tools/install/ и откройте новый терминал.

```sh
./scripts/setup
cargo run
curl http://localhost:8080/
curl http://localhost:8080/healthz
./scripts/check
```

Если Cargo не найден: `export PATH="$HOME/.cargo/bin:$PATH"`.
Версия Rust и компоненты закреплены в `rust-toolchain.toml`.
Сменить порт: `PORT=3000 cargo run`. По умолчанию сервер слушает `0.0.0.0:8080`.
`/healthz` проверяет только доступность процесса, не состояние блокчейна.

## Переменные окружения

При запуске приложение загружает `.env` из текущего рабочего каталога
до запуска Tokio. Запускайте `cargo run` из корня репозитория.
Для локальных настроек скопируйте `.env.example` в `.env`, если его ещё нет,
и заполните значения у себя. Приложение использует `PORT`, `GONKA_REST_URL` и `GONKA_RPC_URL`.

Переменные, заданные в окружении, имеют приоритет над `.env`:
`PORT=3000 cargo run` переопределит порт из файла.
Отсутствующий `.env` допустим; ошибка чтения или синтаксиса останавливает запуск
с сообщением `Failed to load .env`, без вывода содержимого файла.

Реальные секреты храните только в локальном `.env` или хранилище секретов
платформы деплоя. `.env` исключён из Git и контекста Docker-сборки.
В `.env.example` добавляйте только названия настроек и безопасные примеры.

## Структура и первые понятия Rust

- `src/main.rs` — запуск процесса, конфигурация порта и остановка сервера.
- `src/lib.rs` — фабрика `create_app()`, создающая HTTP-приложение Axum.
- `tests/` — проверки ответов API без запуска сетевого сервера.
- `scripts/` — установка хуков и общая команда проверок для локальной работы и CI.
- `docs/` — архитектура, план небольших PR и подготовка деплоя.

Cargo управляет зависимостями, сборкой и тестами; `Cargo.lock` фиксирует их версии.
`async fn` описывает асинхронную функцию; `.await` ждёт завершения операции.
`Result` представляет успех или ошибку; `?` возвращает ошибку вызывающей функции.
`Router` связывает HTTP-пути с обработчиками. Factory здесь — обычная функция,
а не иерархия классов: позже она сможет принимать зависимости приложения.

## Проверки

`./scripts/check` проверяет формат, Clippy (включая pedantic) и тесты.
Предупреждения запрещены, `unsafe`, `unwrap` и `expect` запрещены линтерами.
После `scripts/setup` эти же проверки запускает pre-commit хук.
Хук требует отсутствия нестейдженных правок отслеживаемых файлов.
CI повторяет проверки независимо от локальных хуков.

Хук `commit-msg` проверяет заголовок коммита (первую строку):
формат Conventional Commits `type(scope)!: описание` и длину меньше 120 символов
(максимум 119, включая тип, scope и пробелы). Scope и `!` необязательны;
тип — в нижнем регистре, например `feat`, `fix`, `docs`, `chore`.
Пример: `feat(api): add health endpoint`. Ограничение длины не касается тела сообщения.

Дальнейшая структура и план: [docs/plan.md](docs/plan.md).
Подготовка Cloud Run: [docs/deploy.md](docs/deploy.md).

### Текущий routing сделки

`GET /v1/deals/{deal}/routing` проверяет текущий маршрут напрямую в сети, включая
полную идентичность сделки и регистрацию в Factory. Возвращает `CONFIGURED`,
`OTHER_RECIPIENT`, `NOT_CONFIGURED` или `HISTORY_UNKNOWN`; ошибки не превращаются
в отсутствие маршрута. Общий deadline — 12 секунд, лимит HTTP — 8 наблюдений.
[Контракт Rust/HTTP, cancellation и интеграция Dashboard](docs/routing.md).
