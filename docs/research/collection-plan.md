# Проверка сети и сбор данных

План на 2026-10-14. Реальные ответы сети пока не получены: адрес Factory и endpoint не подтверждены. Нужны только публичные адреса и read-only доступ; seed/private key не требуются.

## Первый замер после получения развёртывания

1. Сохранить chain ID, runtime/version, endpoint без секретов, время UTC и высоту H. Проверить синхронизацию ноды и минимальные доступные высоты отдельно для состояния, блоков, результатов и tx index.
2. Проверить Factory ContractInfo: admin отсутствует, code ID/checksum совпадают с deployment evidence. Прочитать Factory config; проверить CW20 TokenInfo и decimals=6. Имя USDT само по себе не подтверждает токен.
3. Прочитать все страницы `list_deals` на одной H, если endpoint поддерживает исторические smart queries. Проверить уникальность ID/адресов; для каждого Deal сверить code ID, отсутствие admin и config.factory.
4. Для первого среза собрать config, state, funding, usdt_payments, release_status; native_status отдельно с собственным статусом ошибки. Сохранять фактическую высоту каждого ответа. Если единую H обеспечить нельзя, пометить срез как несогласованный по высоте.
5. Получить успешную tx создания и доступные tx переходов; проверить emitter `_contract_address`, префикс события, атрибуты, result code=0. Не принимать похожее событие от постороннего контракта.
6. Проверить `tx_search` с пагинацией и ограничением по высоте. Если индекс недоступен, проверить `block`/`block_results` для последовательного обхода. Отсутствие выдачи не считать доказательством отсутствия сделок или событий.
7. Проверить четыре native gRPC-запроса: GetCurrentEpoch, ListClaimRecipients(Host), EpochPerformanceSummaryByParticipant(Host,E), TotalVestingAmount(Deal). Сохранить ошибки отдельно от нулей; protobuf pin не равен SHA runtime.
8. Измерить p50/p95 latency, число сделок, объём ответов, лимиты RPC и глубину истории. После этого выбрать период обновления и оценить расходы.

Для N сделок стартовый минимальный срез config+state+payments требует примерно `1 + ceil(N/50) + 3N` smart queries без проверки code/token; все семь Deal queries — `1 + ceil(N/50) + 7N`. Полный опрос каждые T секунд даёт примерно это число / T запросов в секунду. Config можно кэшировать после проверки неизменяемости.

## Предлагаемый сборщик

Первичный обход Factory восстанавливает список и текущие состояния без полной истории. Историю начинаем с подтверждённой высоты развёртывания; если архив недоступен, явно публикуем `history_from_height` и неполноту истории.

Обрабатывать подтверждённые блоки последовательно, сохранять raw events и продвигать checkpoint атомарно с записью результата. Для tx events ключ дедупликации: chain ID + height + tx index + event index; отдельно хранить hash блока и tx. Проверять непрерывность и останавливать продвижение при конфликте hash. Повтор после сбоя не создаёт дубли.

WebSocket можно добавить для малой задержки; после разрыва дочитывать от checkpoint. `tx_search` зависит от конфигурации индексатора: `null` отключает индекс, `psql` не обслуживает RPC search. Это подтверждено [CometBFT v0.38.17](https://raw.githubusercontent.com/cometbft/cometbft/v0.38.17/docs/app-dev/indexing-transactions.md); версию целевой сети ещё нужно сверить.

После событий перечитывать затронутые сделки; периодически сверять весь реестр и состояния, включая completed. Ошибка RPC оставляет последний успешный снимок со stale/error, а не превращает его в пустой результат. Разделять `snapshot_height` и `events_indexed_through_height`.

Приёмка сборщика: повторный прогон без дублей; восстановление после сбоя; ошибка native query не теряет state; все сделки Factory представлены; событие чужого emitter отклоняется; пробел истории и устаревшие данные видны клиенту. Образцы ответов записывать как реальные fixtures только после запроса, не подменять синтетическими.
