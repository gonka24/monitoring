# План разработки

Каркас оформлен небольшими коммитами; origin подключён к gonka24/monitoring.
Первый коммит опубликован в main; остальные пока локальные. PR не создавались.
Для следующих PR: цель ≤50 строк,
50–100 нежелательно, >100 запрещено. Размер считаем по добавлениям и удалениям.

Состав подготовленного каркаса:
1. Manifest и закреплённый toolchain.
2. HTTP-фабрика и запуск сервера.
3. Тесты HTTP-контракта.
4. Форматирование, редактор и ignore-файлы.
5. Скрипты проверок и pre-commit.
6. CI.
7. Dockerfile и инструкция деплоя.
8. README и план развития.

Cargo.lock исключён из подсчёта размера PR по согласованию с пользователем.
Файл сохраняем в репозитории для воспроизводимой сборки; остальные файлы
учитываем по общему правилу.

После каркаса:
- Изучить сеть, контракты, адреса, события и доступность истории.
- Определить модель deal: идентификатор, участники, состояние, события.
- Выбрать RPC/индексатор и способ восстановления после пропусков и реорганизаций.
- Выбрать хранилище, частоту обновления, пагинацию и лимиты API.
- Спроектировать защиту публичного API и контроль расходов.

Каталоги добавляем вместе с работающим кодом: `domain/` — сделки и события,
`network/` — чтение сети, `storage/` — хранение, `api/` — HTTP-обработчики.
Фабрика приложения будет связывать эти зависимости.
Не определяем поля сделки и технологию хранения до исследования контрактов.
